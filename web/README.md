# Свои вина — сканер этикеток российских вин

Mobile-first веб-приложение в стиле портала [vino-svoe.ru/wines](https://vino-svoe.ru/wines): каталог 2112 российских вин и поиск вина по фото этикетки.
Распознавание вынесено в отдельный микросервис [`../ml`](../ml/README.md) (FastAPI). Пока в нём заглушка с финальным API, модель подключается без изменений фронтенда.

## Что умеет

| Экран | Путь | Что делает |
|---|---|---|
| Каталог | `/wines` | блок сканера «Сканировать / Загрузить фото», фильтры (цвет, сладость, регион, сорт, производитель, блюда), поиск, «Показать ещё» |
| Камера | `/scan` | видоискатель с рамкой, затвор, фонарик, галерея. Без доступа к камере — системная камера `<input capture>` |
| Результат | `/scan/result` | загруженное фото и мини-карточки. Одна бутылка или одна явно преобладающая (по площади и близости к центру): точка на ней и чистая плашка под фото. Несколько похожих бутылок в переднем ряду: цветные кружки с номерами на бутылках и такие же у карточек в колонке справа. Мелкие бутылки сзади не отмечаются. Нет в каталоге — честная плашка и аналоги |
| Карточка | `/wines/:slug` | характеристики как на портале + функции после скана: сверка с этикеткой (цвет, сладость, год), «Цифровой сомелье», аналоги других виноделен, «Ещё от винодельни». Своя оценка — только у вина, которое вы сканировали (добавляет его в коллекцию); строка «Для вас» по вкусовому профилю |
| Личный кабинет | `/my` | «Коллекция» — вина, которые вы оценили после скана (добавить можно только из сканера); «Мой вкус» — вкусовой профиль по анкете из 5–6 простых вопросов, уточняется оценками, и «Вина в вашем стиле»; история сканов. Хранится на устройстве, без регистрации |

Фото можно также перетащить на блок сканера или вставить из буфера (Ctrl/Cmd+V) — удобно на десктопе.

## Запуск локально

```bash
# 1. сервис распознавания (заглушка), порт 8000
cd ml && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --port 8000

# 2. сайт, порт 3000
cd web && npm install && npm run dev
```

`web/.env`:
- `NUXT_ML_URL` — адрес сервиса распознавания, можно несколько через запятую (пробуются по порядку);
- `NUXT_ML_TIMEOUT_MS` — сколько ждать ответа: для локального Mac нужно около 30 000, для T4 хватит 8 000.

Если адресов нет ни в `NUXT_ML_URL`, ни в `ml-url.txt`, сайт работает во встроенном демо-режиме: псевдорезультат по хешу фото, без детекции.

### Сервис на Kaggle T4

1. Запустите ноутбук `ml/kaggle/serve_t4.ipynb` (инструкция: `ml/kaggle/README.md`). Через ~2 минуты он напечатает `PUBLIC URL: https://<слова>.trycloudflare.com`.
2. Подключите адрес без перезапуска сайта:

   ```bash
   echo "https://<слова>.trycloudflare.com" > web/ml-url.txt
   ```

   Файл перечитывается при каждом скане. Адрес из него пробуется первым, `NUXT_ML_URL` (например, локальный `http://127.0.0.1:8010`) остаётся запасным.
3. Проверка: `curl localhost:3000/api/ml/status` покажет, какие адреса живы и какой активен.

Если T4 ещё грузится или туннель пропал, сайт сам переключается на запасной адрес. Упавший адрес проверяется через `/health` раз в 15 с и возвращается в работу, как только ответит. Когда сессия Kaggle закончится, удалите `web/ml-url.txt` или впишите новый адрес.

Всё вместе в Docker: `docker compose up --build` из корня репозитория → http://localhost:3000, Swagger сервиса — http://localhost:8000/docs.

## API сайта

Совпадает по форме с API портала, чтобы фронтенд можно было переключить на него.

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/wines?page&limit&search&color&sweetness&region&grape&manufacturer&dish` | `{currentPage,totalPages,itemsPerPage,totalItems,items}` |
| GET | `/api/wines/filters` | группы фильтров со счётчиками |
| GET | `/api/wines/:slug` | полная карточка |
| GET | `/api/wines/:slug/similar?mode=similar\|analogs&size` | похожие (analogs — только другие винодельни) |
| POST | `/api/wines/for-taste` `{colors,sweet,sparkling,body,dishes,exclude,limit}` | «Вина в вашем стиле» для вкусового профиля кабинета |
| POST | `/api/wines/search-by-photo` (multipart `file`) | ответ ML (у каждой бутылки свой `match`) + `detection.bottles[].wine` (мини-карточки) + `wine` и `analogs` главной бутылки + `server_ms` |
| POST | `/api/predict` (multipart `file`/`image` или сырое тело) | **`{"slug": "wine-slug"}`** — формат скрипта организаторов, `""` если не найдено |
| POST | `/api/sommelier` `{slug, food, occasion}` | `{verdict, serve, summary, count, recommendations, query}` — еда только из рекомендованной винодельней, подборка того же стиля от других виноделен |
| GET | `/api/ml/status` | какие адреса ML настроены и живы, какой сейчас активен |

Confidence (топ-1, отрыв, топ-5) есть только в ответе API, в интерфейсе его не показываем (по ТЗ).

## Тестирование

- Режим «не найдено» в dev: `localStorage.setItem('svoe-vino:force', 'not_found')` (или `found`), затем скан. Параметр доходит до сервиса как `?force=` и работает только при `ALLOW_FORCE=true` (в docker-compose выключен).

### Оценка качества (Track A, скрипт организатора)

- `scripts/eval_service.py --subset exact|probable|same_line|all --limit N` — прогоняет фото из `wine_seg/runs/rp/evalds/rp_eval.csv` через `/api/predict`
  (как скрипт организатора: одно фото — один POST — `{"slug"}`, время запроса) и `/api/wines/search-by-photo` (топ-5 для R@5/F1@5).
  Пишет `data/metrics.json` (читает `GET /api/metrics` → `/metrics`, скрытая страница для демо) и печатает markdown-таблицу по подвыборкам.
- `scripts/eval_service.sh [папка_с_фото] [url] [out.csv]` — упрощённая копия скрипта организатора на bash/curl: по кругу шлёт фото в `/api/predict`,
  пишет `file,slug,time_total_s` в CSV. Для полных метрик (F1, R@5, перцентили) используйте `eval_service.py`.

## Структура

```
web/
  app/pages/          wines/index, wines/[slug], scan/index, scan/result, my
  app/components/     шапка, нижняя пилюля, поиск, меню, сканер, карточки, фильтры, сомелье
  app/composables/    useScan (нормализация фото → API → результат), useMyWines (личный кабинет в localStorage: коллекция, анкета, история)
  server/api/         каталог, поиск по фото, predict, сомелье
  server/utils/       catalog (единая точка замены на PostgreSQL/Strapi), similar, recognizer (клиент ML)
  data/               выгрузка каталога (scripts/build_catalog.py)
  public/img/wines/   фото бутылок каталога (webp)
```

Архитектура и планы по модели — в [ARCHITECTURE.md](ARCHITECTURE.md).
